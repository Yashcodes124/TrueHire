# Deployment Guide

TrueHire deploys as two independent services backed by PostgreSQL 15:

- **Backend API (`server/`):** Node.js web service defined in `render.yaml` (Render).
- **Frontend SPA (`client/`):** Static Vite bundle configured by `client/vercel.json` (Vercel).
- **Local Database:** PostgreSQL 15 container defined in `docker-compose.yml`.
- **CI/CD Pipelines:** GitHub Actions workflows in `.github/workflows/`.

---

## Production Security Checks (Fail-Closed)

When `NODE_ENV=production`, `validateProductionEnv()` in `server/src/config/env.ts` runs at startup and exits with code `1` if any of these checks fail:

1. **`JWT_SECRET`** must be explicitly set, non-default, and at least **32 characters** long.
2. **`DATABASE_URL`** must be explicitly set to a non-default `postgresql://` or `postgres://` connection string.
3. **`CLIENT_URL`** must not contain the wildcard `*` (required when CORS `credentials: true` is enabled).

Additional production configuration notes:
- Set a separate **`JWT_REFRESH_SECRET`** (auto-generated by `render.yaml`).
- Set **`DIRECT_URL`** when using a pooled database URL (e.g., Supabase PgBouncer or Neon pooler) so `npx prisma migrate deploy` connects directly.
- Set at least one AI provider key (`GROQ_API_KEY` or `AI_API_KEY`), and optionally `NVIDIA_API_KEY` / `GEMINI_API_KEY` for automatic failover.
- `AI_E2E_MOCK` is ignored whenever `NODE_ENV=production`.
- To enable Sentry error reporting, install `@sentry/node` in `server/` and `@sentry/react` in `client/`, then set `SENTRY_DSN` and `VITE_SENTRY_DSN`.

## Backend Deployment on Render (`render.yaml`)

The repository root includes a Render Blueprint (`render.yaml`) for the `truehire-api` service:

| Setting | Configured Value |
| --- | --- |
| **Root Directory** | `server` |
| **Build Command** | `npm install && npx prisma generate && npm run build` |
| **Start Command** | `npx prisma migrate deploy && npm start` |
| **Health Check Path** | `/api/health` |
| **Auto-generated Secrets** | `JWT_SECRET`, `JWT_REFRESH_SECRET` |

### Manual Dashboard Secrets (`sync: false` in `render.yaml`)

Configure these in the Render dashboard before the first deploy:

- `DATABASE_URL` — runtime PostgreSQL connection string
- `DIRECT_URL` — direct PostgreSQL connection string for Prisma migrations
- `CLIENT_URL` — exact production frontend origin (e.g., `https://your-app.vercel.app`)
- `SERVER_URL` — public Render service URL (e.g., `https://truehire-api.onrender.com`)
- `AI_API_KEY` (or `GROQ_API_KEY`) — primary provider API key
- `NVIDIA_API_KEY` — optional secondary failover key

Verify the deployment:

```bash
curl https://<your-render-service>.onrender.com/api/health
```

Confirm `"status": "ok"`, `"database": "connected"`, and `"aiConfigured": true`.

## Frontend Deployment on Vercel (`client/vercel.json`)

1. Import the repository in Vercel and set **Root Directory** to `client`.
2. Build settings (auto-detected for Vite):
   - **Build Command:** `npm run build` (`tsc && vite build`)
   - **Output Directory:** `dist`
3. Set environment variables in Vercel Project Settings:
   - `VITE_API_BASE_URL=https://<your-render-service>.onrender.com/api`
   - `VITE_SENTRY_DSN` (optional, only if `@sentry/react` is installed)
4. `client/vercel.json` handles:
   - Client-side SPA routing rewrites (`/(.*)` -> `/index.html`)
   - Security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`)

## Local Containerized Database (`docker-compose.yml`)

`docker-compose.yml` provisions PostgreSQL 15 (`career_lens_postgres`) with a `pg_isready` health check and persistent `postgres_data` volume:

```bash
# Requires POSTGRES_USER and POSTGRES_PASSWORD in root .env
docker compose up -d postgres
```

Default port mapping is `${POSTGRES_PORT:-5433}:5432`.

## CI/CD Workflows (`.github/workflows/`)

| Workflow | Trigger | What It Runs |
| --- | --- | --- |
| `ci.yml` | Push & PR to `main`, `master` | **server-verify:** `npm ci`, `npx prisma generate`, `npx tsc --noEmit`, `npm test` (Node 20).<br>**client-verify:** `npm ci`, `npm test --if-present`, `npm run build` (Node 20). |
| `cd.yml` | Push to `main`, manual `workflow_dispatch` | Runs server + client verification and build, then triggers optional `RENDER_DEPLOY_HOOK_URL` and `VERCEL_DEPLOY_HOOK_URL` GitHub Actions secrets via `curl` (skips cleanly if unset). |
| `e2e.yml` | Pull request, manual `workflow_dispatch` | Starts a Postgres 15 service container, pushes Prisma schema (`prisma db push`), installs Playwright Chromium, runs `npm run test:e2e` with `AI_E2E_MOCK=true`, and uploads `client/playwright-report/` on failure. |

## Post-Deployment Smoke Checklist

- [ ] `GET /api/health` returns `200` with `database: "connected"` and `aiConfigured: true`.
- [ ] Register, login, token refresh (`POST /api/auth/refresh`), and logout work from the Vercel origin without CORS errors.
- [ ] Resume upload/paste, job matching, and mock interview completion update `/readiness` and `/radar`.
- [ ] Admin user can access `/admin` and trigger `POST /api/jobs/sync`; non-admin users receive `403` on `/api/admin/*` and `/api/jobs/sync`.
- [ ] Background ATS sync runs cleanly (note: `jobSyncScheduler.ts` runs in-process per web instance; if scaling horizontally to multiple instances, move sync triggering to an external cron calling `POST /api/admin/job-syncs/run`).
